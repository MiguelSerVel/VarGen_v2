# VarGen v2
This project aims to update and improve the VarGen R package (https://github.com/MCorentin/vargen) published at Cranfield University.

## Updates
New updates have been added to the existing VarGen code to restore interaction with current version of resources and R dependencies. The udpates are also reflected in the files downloaded and processed by the functions `vargen_install`, `vargen_pipeline` and `vargen_custom`

### GTEx
1. Introduction of the latest version of the GTEx Portal: version 10 (available at:  https://storage.googleapis.com/adult-gtex/bulk-qtl/v10/single-tissue-cis-qtl/GTEx_Analysis_v10_eQTL.tar )
2. Corrected an issue were version 8 was downloaded regardless of the selected version.
3. Updated the `list_gtex_tissues` function to consider files from version 10 which have a different naming convention
4. Updated the `get_gtex_variants` function to read .parquet files
5. Introduced the use DuckDB R package to read and load file information much faster

### FANTOM5
1. Changed the strategy to retrieve regulatory SNPs. The original file containing associations between genes and enhancers is no longer available in online repositories. A new approach was considered using two files:
    - Genomic locations of promoters (available at: https://fantom.gsc.riken.jp/5/datafiles/reprocessed/hg38_latest/extra/CAGE_peaks_expression/hg38_liftover+new_CAGE_peaks_phase1and2_ann.txt.gz)
    - Transcribed genomic location of enhancers (available at: https://fantom.gsc.riken.jp/5/datafiles/reprocessed/hg38_latest/extra/enhancer/F5.hg38.enhancers.bed.gz )
2. This new strategy involves the use of a new user-adjustable parameter, `fantom_enhancer_gap`, which specifies the number of bases used to search for enhancers in relation to promoters’ locations. It is set by default to 100 kb.
3. Replaced function `prepare_fantom` with `prepare_fantom_promoters` and `prepare_fantom_enhancers` to handle data from the respective files.
4. Replace the parameter `corr_threshold` with the parameter `score_threshold`, set by default to 5. New files do not contain information about the correlation between enhancers and genes.
5. Updated the `get_fantom5_variants` function to consider both promoters and enhancers using the data from the new files
6. Removed the function `get_fantom5_enhancers_from_hgnc`

### Utils
1. Removed the `host` parameter from the `connect_to_gene_ensembl` and `connect_to_snp_ensembl` functions
2. Added a `version` parameter to `connect_to_snp_ensembl` and set by default to 106. It allows to retrieve data from archived ENSEMBL datasets since latest version may miss some phenotype information.
3. Introduced the `annotate_dataframe` function as a wrapper of the `annotate_variants` to facilitate merging annotations to an existing data frame containing variant information.
4. Corrected issues in the `vargen_visualisation` function with the GViz package syntax
5. Updated the `vargen_visualisation` function to prevent figures from the same gene to overwrite each other when saving them.
6. Added comments to improve readability across mutliple files

### Comparison between versions
A SNP search with `vargen_pipeline` was performed on the original VarGen code (with the minimum updates and a saved copy of the enhancer associations file) and VarGen v2. Thhe search was based on the following inputs: 
  - OMIM ID 222100 corresponding to “type 1 diabetes mellitus”
  - Pancreas tissues from the GTEx repository
  - GWAS term: “Type 1 diabetes”

Results indicate a higher number of SNPs retrieved by VarGen v2

## New features
Given the potential clinical relevance of SNPs sets retrieved by VarGen, upgrades have aimed to facilitate the use of its output in the context of variant analysis studies. New functionalities include functions for integrating VarGen’s output with GWAS summary statistic files and VCF files provided by the user. 

### VCF files
A new R file vcf.R containing functions to manage data from VCF files was added to the repository. Since VCF files can be computationally intensive these functions process data with DuckDB.

The main function `study_vcf` takes the path to a VCF file, a variant master list generated by VarGen, and an optional GWAS summary statistics file and ultimately, returns a data frame containing annotated variants from the master list that were identified in the VCF file. Additionally, it can also annotate variants with information obtained from a specific GWAS summary statistics file.

### GWAS summary statistics files
Results from GWA studies are often reported in summary statistic files which can be used to compare the variants found in a VCF file with the variants reported earlier by relevant GWA studies.  Functions to download and load this data into the R environment are located in the gwas.R file.

The new function get_gwas_list searches for relevant GWA studies in the GWAS Catalog using a list of keywords related to the traits of interest and the 
ethnicity of the population participant in the study as filters. 

Along with other information, the output contains a GWAS ID, which can be used to download the summary statistics file with the function `get_gwas_files`. If the required file is 
not publicly available, the function will warn the user. 

Functions that handle data from the GWAS summary statistics files use DuckDB.
